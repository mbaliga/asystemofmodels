# Vendored Hyle design tokens

These two files are **vendored, not hand-written** — a copy of the token surface of
the Hyle Design System, brought in so asom's UI theme seam
(`xyz.mdhv.asom.ui.theme`) can be driven by Hyle's design tokens.

| File | Origin |
| --- | --- |
| `tokens/HyleTokens.kt` | Generated by Style Dictionary in the Hyle repo (`hyle/src/main/java/dev/aarso/hyle/tokens/HyleTokens.kt`) — copied **verbatim**. |
| `Argb.kt` | The `typealias Argb = Long` from Hyle's `Hyle.kt` (extracted; the rest of that file is Hyle's material contract, not vendored). |

## Source

- Repo: `mbaliga/Hyle-Design-System`
- Publishable coordinate: `dev.aarso:hyle:0.2.0`
- Vendored from commit: `0fade5b3dbb1ac445d3d06c9b9af22b7903aab5e`

## Why vendored (and not a Gradle dependency)

`dev.aarso:hyle` has no remote Maven artifact — Hyle's intended consumption is
`git submodule` + Gradle `includeBuild`. asom deliberately avoids that here:
vendoring keeps the build dependency-minimal with no build-time network fetch
(consistent with the no-automatic-egress ethos, Invariant §1.1–§1.3), keeps the
pure-JVM build path untouched (brief §3), and sidesteps Hyle's `minSdk 31` vs
asom's `minSdk 29`. It mirrors how asom single-sources `fixtures/catalogue.v1.json`.

## Re-syncing when Hyle tokens change

1. In the Hyle repo: edit `tokens/*.json`, then `npm run tokens:build`.
2. Copy the regenerated `hyle/src/main/java/dev/aarso/hyle/tokens/HyleTokens.kt`
   over `tokens/HyleTokens.kt` here (drop-in — do not edit it by hand).
3. Run `./gradlew :app:testDebugUnitTest` — `HyleSeamTest` re-checks the §1.6
   binding (violet + cyan only; never a red/green hue). Update the mapping in
   `xyz/mdhv/asom/ui/theme/HyleSeam.kt` if token names changed.
