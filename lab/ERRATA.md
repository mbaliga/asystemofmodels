# lab ERRATA: spec defects met by the `lab-skeleton` track (L0.1 and the shared skeleton)

Where a spec defect (`docs/design/mesh/REVIEW_ROUND3.md`, or a defect found while building) touches what this track
implements, the CONSERVATIVE reading was taken and is recorded here. Nothing was silently guessed. Later lab tracks
add their own rows below, with their own ids.

| ERR-ISO-1 | LAB_SPEC 2.4 check 4, 8.2 step "Isolation checks 1, 3, 4"; R3-CONFORMANCE-2 | `git diff --exit-code` after a checkout compares the working tree with the index, which is clean on a fresh checkout, so it passes even when the change itself edits `settings.gradle.kts`, `core/` or `ci.yml`. The check could not fail. | Check 4 is `lab/tools/isolation.py`: every protected path (`core server app vault pairing storage ledger client client-cloud sample-client gradle settings.gradle.kts build.gradle.kts gradle.properties .github/workflows/ci.yml`) is compared byte for byte (blob id, executable bit, file set incl. untracked and deleted files) against the same path at the commit in `LAB_BASE_SHA` (environment variable, else `lab/LAB_BASE_SHA`, value `1963166c500d9e83b6b5b076bb3c11263ef3e429`). It fails LOUDLY (exit 2) when the base is not a full commit id, does not exist locally (shallow clone), or is not an ancestor of HEAD. `isolation.py --selftest` runs negative controls on a synthetic repository (committed edit of settings, untracked file, deleted file, edited ci.yml, flipped exec bit, non-ancestor base, missing base) and CI runs it before the real check. `lab.yml` uses `fetch-depth: 0`. **Still not covered:** a root edit that is already part of the pinned base, and a later reviewed move of the pin. When the branch is rebased or squash-merged the pin no longer describes history: the check then fails loudly and `lab/LAB_BASE_SHA` must be re-pinned in a reviewed commit that shows the protected tree unchanged. |
