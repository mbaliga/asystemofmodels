# desktop/packaging/linux ERRATA: spec defects met by the `linux-packaging-dl3` track and the reading taken

Where a spec defect (`docs/design/mesh/REVIEW_ROUND3.md`, or one found while building) touches what DL3 implements, the
CONSERVATIVE reading was taken and is recorded here. Nothing was silently guessed. The desktop-wide table is
[`../../ERRATA.md`](../../ERRATA.md); ids here are `ERR-DL3-n`.

| id | spec section | defect | conservative choice taken |
|---|---|---|---|
| ERR-DL3-1 | PLATFORM_PLAN 3 DL3 gate 6 ("`jdeps --print-module-deps` output equals `jlink-modules.txt`"); linux.md 7.4 | jdeps cannot be equal to a usable list in either direction. It OVER-reports: `java.desktop` (only `com.typesafe.config.impl.ConfigBeanImpl` -> `java.beans`, reached only through `ConfigBeanFactory`, which nothing in `:server`, `:node`, `:node-core` calls) and `java.instrument` (`kotlinx.coroutines.debug.internal.AgentPremain`, `requires static`). It UNDER-reports: it cannot see service providers, so `jdk.crypto.ec` (ES256, ECDHE, TLS 1.3 key shares) is invisible to it, and a runtime without that module passes every compile and unit test and then fails (`EC KeyPairGenerator not available`, measured, see the report). | `jlink-modules.txt` has three sections. `check-jlink-modules.sh` requires jdeps == `[derived]` + `[excluded]` EXACTLY, so any new module fails until a human files it; `[excluded]` and `[added]` lines each need a reason comment; `jdk.net` (ERR-DL2-9) and `jdk.crypto.ec` are pinned. `java.desktop` (about 20 MB, AWT and Swing, no use) and `java.instrument` are excluded. Residual risk: a future call into `ConfigBeanFactory` would fail at run time on the packaged runtime; jdeps would not warn, because the class was already reported. Nothing calls it today. |
| ERR-DL3-2 | PLATFORM_PLAN 3 DL3 gate 4 (`self-test: native OK (none), ES256 OK, TLS1.3 pinned handshake OK` per distro) | The node's selftest has no native-loader line (DL4), no ES256 line and no pinned-identity handshake (mesh tracks). The expected string cannot be produced, and printing it would be a fabricated result. | `distro-matrix.sh` prints what really ran: the node's own selftest summary (`selftest: N ok, M not-yet-implemented, 0 failed`) and `test/probe/RuntimeProbe.java`, run on the SHIPPED runtime: `jdk.net SO_PEERCRED` (a real AF_UNIX round trip), ES256 (DER and P1363 forms, tamper rejection) and a TLS 1.3 in-memory `SSLEngine` handshake with an EC certificate and host-name checking. The probe line says in words that it is NOT the mesh pinned-identity handshake. W08 against the packaged node (linux.md 7.4; R3-OVERCLAIM-6) is not done here. |
| ERR-DL3-3 | linux.md 3.2 ("`-XX:ErrorFile` under the state dir baked into the launcher by jpackage `--java-options`") | The state dir differs per mode (SYSTEM `/var/lib/asom`, USER `$XDG_STATE_HOME/asom`) and a jpackage launcher expands no environment variable (only `$APPDIR`, `$ROOTDIR`, `$BINDIR`). One baked path is wrong for one of the modes, and an unwritable `ErrorFile` makes HotSpot fall back to the working directory or `/tmp`, where an `hs_err` file (environment, registers, stack fragments, possibly prompt text) would sit. | `-XX:ErrorFile=/dev/null`, verified on this JDK: with it a forced VM abort wrote NO `hs_err` file anywhere and printed only the short fatal-error summary to stdout (which the system unit sends to the null device); with a real path it wrote an 81 KB log. Cost: no crash log for diagnosis. A later step can add per-mode launchers or a config-dir option; until then the owner can edit `lib/app/asom-node.cfg` (`java-options=`) to debug a crash. The other baked options: `-Dfile.encoding=UTF-8`, `-XX:-CreateCoredumpOnCrash`, `-Xmx384m` (as in linux.md 3.2). |
| ERR-DL3-4 | PLATFORM_PLAN 3 DL3 gate 1 (`app image: build/asom-desktop-<ver>-linux-x86_64`) | `build/` relative to what is unstated, and a root-level `build/` would put output outside this track's directory. | The default output directory is `desktop/packaging/linux/build` (git-ignored by `desktop/.gitignore`). The script prints `app image path: <absolute>` and then `app image: build/asom-desktop-<ver>-linux-<arch>` (relative to `desktop/packaging/linux`) when the default directory is used; with `--out` it prints the full path instead. |
| ERR-DL3-5 | linux.md 8.1 ("`apt purge` or `asom uninstall --purge` deletes `/var/lib/asom` after a TTY confirmation that names what is lost") | A dpkg or rpm maintainer script has no terminal to confirm on (`apt purge -y` is routinely non-interactive), and the confirmation is exactly what stops a silent loss of the node identity (re-pairing) and the ledger. `asom uninstall --purge` is a CLI command that does not exist yet. | Package removal and `apt purge` NEVER delete `/var/lib/asom` or the system user `asom`; `postremove.sh` says what was kept and how to delete it by hand. The per-user route has the confirmed purge: `uninstall.sh --purge` reads the exact phrase from `/dev/tty` (never stdin), names the ledger and the identity, and refuses without a terminal, changing nothing. Tested on a real pty, including the wrong-phrase and no-terminal refusals. |
| ERR-DL3-6 | linux.md 8.4 ("tarball: ... restart the service if running") vs "installers never enable or start anything" | A restart hits a lender that may be mid-request, and the owner did not ask for it. | `install.sh` restarts nothing. If it sees an active user unit it prints the command to restart it yourself. The deb and rpm keep the spec's `try-restart` on UPGRADE only (a stopped node stays stopped; checked with stubs and, in CI, on a real systemd VM: a reinstall leaves it inactive). |
| ERR-DL3-7 | PLATFORM_PLAN 3 DL3 gate 5 (`systemctl is-enabled asom` -> `disabled` after `apt install`) | Needs a real systemd. This build container has no PID 1 systemd, and containers in `install-matrix` have none either. | The claim is CI-ONLY: the `package-linux` job installs the deb on the runner VM and asserts `disabled` and `inactive`. What was checked HERE: no `.wants` or preset path in the deb or the tarball install, maintainer scripts run against stub `systemctl` never call enable, start, restart or preset (19 checks in a private mount namespace), and `UnitFilesTest` (DL2) scans every non-test `.sh` under `packaging/linux` for those verbs. |
| ERR-DL3-8 | linux.md 8.1 (`Depends`), LD-3 (Temurin 21) | The system libraries the runtime needs depend on the JDK build. This container has Ubuntu's OpenJDK 21.0.10 (needs `libc`, `libm`, `libz`, `libstdc++`, `libgcc_s`), not Temurin, which is what CI and releases use. | `Depends` is those five libraries' packages (deb: `libc6, libstdc++6, libgcc-s1, zlib1g`; rpm: `glibc, libstdc++, libgcc, zlib`). `check-native-deps.sh` fails the build if a different JDK vendor's image needs a library outside that set, so the Depends line is corrected instead of a bare server failing at install. `build-app-image.sh` warns when the runtime is not Eclipse Temurin; every image built here is LAB evidence only. |
| ERR-DL3-9 | PLATFORM_PLAN 3 DL3 ("nfpm ... verify its checksum") | The checksum can only be compared with the release's own `checksums.txt`, which is the same origin as the file: it detects a corrupted or later-changed download, not a compromised release. | nfpm 2.41.3 (Linux x86_64 and arm64) is pinned by SHA-256 in `fetch-nfpm.sh`; the values are the release's own `checksums.txt` entries, and the downloaded file matched (LAB). The file is not extracted or run until the check passes. nfpm 2.41 does not expand `${VAR}` in `contents` `src` and `dst`, so `build-packages.sh` resolves every variable itself and fails on any left over. |
| ERR-DL3-10 | linux.md 8.1 and 8.4 (`asom upgrade --from <file>`, `asom rollback`, `asom uninstall`, `asom install --system`) | These are CLI commands of DL2 that do not exist in this wave (the CLI answers `NOT_IMPLEMENTED`). | `install.sh` performs the upgrade and keeps `previous` (a symlink to the old version directory) so a later `asom rollback` has something to swap to; `uninstall.sh` replaces `asom uninstall`. Nothing prints or implies those CLI commands work. |
| ERR-DL3-11 | linux.md 8.1 (image layout: `lib/native/...`, `native.sha256`, `share/doc/{LINUX.md,STEAM_DECK.md,LICENSE,NOTICE,THIRD-PARTY.txt}`) | The native tree belongs to DL4, and no licence audit exists. | No `lib/native` and no `native.sha256` (there is no native code; the selftest does not claim any). `share/doc` holds `LINUX.md` and `STEAM_DECK.md` copied from `desktop/docs`, the Apache-2.0 `LICENSE`, a `NOTICE` that says UNSIGNED, and a `THIRD-PARTY.txt` that is an INVENTORY of jar names and SHA-256 sums, labelled "not a licence audit". jpackage's default icons (`lib/asom-node.png`, `lib/asom.png`) are its generic Java icon, not branding. |
| ERR-DL3-12 | PLATFORM_PLAN 3 CI (`install-matrix` lists `ubuntu:26.04`) vs desktop/ERRATA.md ERR-DL2-12 (the `ubuntu-26.04` RUNNER label is unknown) | A container image tag and a runner label are different things. | `ubuntu:26.04` is in the install-matrix list because the tag exists on Docker Hub (HTTP 200 from the registry API, 2026-09-30); its contents were not inspected and the leg has never run. The runner stays `ubuntu-24.04`. |
| ERR-DL3-13 | R3-CONFORMANCE-13 (work built ahead of open rulings is not labelled) | The package ships the polkit rule (D28 open) and the units for a control socket the node does not start (D23/D25 open). | Both are shipped exactly as DL2 wrote them, DISABLED, with no listener; the package adds no policy of its own. The rule grants nothing until the owner enables the unit and something holds a lock; removing the file withdraws it. |
| ERR-DL3-14 | linux.md 8.3 (`SHA256SUMS` signed offline; attestations) | Nothing here can sign, attest or notarise. | Every artifact and artifact NAME is labelled UNSIGNED, not for release; `UNSIGNED-NOT-FOR-RELEASE.txt` ships beside the files; `install.sh` says `signature NOT CHECKED` rather than implying a check. Builds are not reproducibility-checked (file mtimes are embedded). |
