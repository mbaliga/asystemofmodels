# macOS ERRATA: spec defects and gaps met by the `macos-mc1-mc2` track, and the reading taken

Where a spec defect (`docs/design/mesh/REVIEW_ROUND3.md`, or a defect found while building) touches what this track implements, the
CONSERVATIVE reading was taken and is recorded here. Nothing was silently guessed. Ids are `MAC-*` so they never collide with
`desktop/ERRATA.md` (the desktop-core track's), `desktop/packaging/windows/ERRATA.md` (`WIN-*`) or `lab/ERRATA.md`. Evidence labels:
`LAB` (Linux container), `CI-APPROX`, `CI-ONLY / NOT RUN` (needs a hosted macOS runner), `NDV` (needs a real Mac).

| id | spec section | defect or gap | conservative choice taken |
|---|---|---|---|
| MAC-SEAM-1 | macos.md 7.2 and 10.1 (`:node-desktop`, `nikStore`, `power` with `Hold`) vs PLATFORM_PLAN 2 and the shipped `DesktopPlatform` | macos.md reads `:node-desktop`; the plan renames it `:node-core`. The seam the plan gives is `paths(mode)`, `nikStore(paths)`, `power()`, `presence()`, `gpuContention()`, `thermal()`, `listenerGate()`, `controlSocket(paths)`, and `NikStore` has only `keyStorage`. | `MacPlatform` implements the REAL seam and adds nothing to it. The Mac-only capabilities are separate types the host owns (`MacNikStore.existing()` and `createAtFirstMeshEnable`, `ServiceRegistration`, `NodeLock`, `MacDoctor`, `MigrationGuard`). The module depends on `:node-core` only (plus what it brings). |
| MAC-SCOPE-1 | R3-CONFORMANCE-13 ("scaffold" stretched; work built ahead of open rulings is not labelled) | MC1 and MC2 include D-v2 content gated by open decisions: the Secure Enclave key tier through a Swift helper (M-D3, D27), the owner control socket policy (D25, D23), the helper and its protocol as new artefacts (M-D11, D23), Homebrew and signing (later steps). | Labelled here as built AHEAD of open rulings. Nothing listens, nothing lends, nothing is created at construction (no key, no directory, no lock file, no process), no owner command enables lending, the helper is spawned only by the first call that needs it and only from an explicitly configured absolute path, and the hardened launcher, signing, packaging, the two-node smoke and the tap are NOT built (marked stubs). "No listener" here covers network sockets AND the control socket: the control socket does not bind at all (MAC-CTL-2). |
| MAC-MODE-1 | macos.md 3.2 (`mode = AGENT \| DAEMON \| DEV`), 3.1 B, 7.2 vs the seam's `HostMode` (SYSTEM, USER, FOREGROUND) | The seam has three modes named for Linux. The dev state is "derived when the node's own signature carries no Team ID; never an argument" (macos.md 7.3 item 2). | USER and FOREGROUND are the per-user agent (the Team-ID group container) when a Team ID is known, and the DEV state directory `~/Library/Application Support/xyz.mdhv.asom-dev` when it is not. SYSTEM is the mode-B LaunchDaemon and is REFUSED (`HostRefusedException`: M2, after S-M5 and M-D2); its layout is computed and tested (`MacPaths.layout(DAEMON, ...)`) but never used. The node refuses root by name and by uid in every mode. |
| MAC-TEAM-1 | macos.md 3.3 a, 11.1 M-D10 (the Team ID names the group container and every signature) | The Team ID is an owner decision that does not exist yet, and the spec says it is "fixed at build time". | OWNER-FILL: no value is in the repository or invented. `MacBuildInfo.teamId()` reads a classpath resource `build-info.properties` that the (later, MC5) signing step writes; this scaffold has none, so every run is a DEV-state run and `asom doctor` says `UNSIGNED BUILD: container protection absent`. It is never read from an environment variable (a variable would let any same-user process name the group container); a test fails the build on a 10-character upper-case literal in main or on a committed resource. A Team ID must match `^[A-Z0-9]{10}$` or the node refuses it. |
| MAC-PATH-1 | `NodePaths` doc ("the identity directory is outside the ledger/state directory") vs macos.md 3.3 a and 7.2 (`<container>/node/nik.se`) | The seam says outside, the spec puts identity in `node/`, a sibling of `ledger/` under one container. | The spec's layout: `<container>/node` is a directory of its own, distinct from `ledger/`, 0700, with a `CACHEDIR.TAG` (restic and borg `--exclude-caches`); the backup exclusion of the container root is a separate helper call whose failure is a state, not an error (AM18 is unverified: Time Machine behaviour is device-only). |
| MAC-PATH-2 | macos.md 3.3 c, 7.5 ("104-byte `sun_path`") | 104 is the array size, which includes the terminating NUL. | The limit is 103 BYTES (counted over UTF-8), refused at layout time. `ControlSocketIT` (macOS) probes the longest path the JDK really binds and asserts the node's limit does not exceed it. |
| MAC-PROTO-1 | macos.md 3.5 (protocol v1 "one JSON object per line; integers only; unknown fields rejected") | The table leaves correlation, framing limits, key order, the error vocabulary and the decode order unspecified. | Written normatively in `helper-protocol/SCHEMA.md`: an OPTIONAL integer `id` echoed by the helper (so `sleep.ack` may overlap a request); members in a fixed canonical order; a closed set of seven codec reject codes and five response error codes; one decode order so both lanes give the same code; lines of at most 131,072 bytes; a CR or LF byte inside a line refused (CRLF is rejected, not tolerated); a final partial line at EOF discarded unanswered; end of stdin is the shutdown. 404 vectors pin it. |
| MAC-PROTO-2 | macos.md 3.5 (`presence.get {ok, hidIdleMs, screenLocked, consoleUserIsSelf}`) | "Unreadable" is not representable, so a helper could only lie with a default (`false`, `0`). | `hidIdleMs`, `screenLocked` and `consoleUserIsSelf` may each be `null` ("unknown"). The node treats every unknown as PRESENT (`console-user-unknown`, `presence-unreadable`). |
| MAC-PROTO-3 | macos.md 3.5 (`power.get {source: "ac\|battery", ...}`, `gpu.get {ok:false, code:"UNAVAILABLE"}`) | A UPS is neither; an unreadable power source has no value. | A UPS is `battery` (backup power, the conservative reading). An unreadable source is the error `UNAVAILABLE`, which the node maps to UNKNOWN, which the desktop rules treat as a block. `batteryPermille` is `null` for a Mac without a battery. |
| MAC-PROTO-4 | macos.md 3.5 (`assert.hold {reason}`) and 2.1 (the assertion is named "asom: lending compute to your paired devices") | A free-form `reason` would let anything that spoke to the helper put any text into `pmset -g assertions`, defeating the watched-object rule. | The `reason` must equal the fixed string byte for byte or the request is refused (`BAD_FIELD`); the client always sends it. `assert.hold` while held is `ok` with no second assertion; `assert.release` while none is held is `ok`. |
| MAC-PROTO-5 | macos.md 3.5 (`se.selftest {ok, verified:true}`; `mem.get`; error shape) | `verified:false` and a Mac with no Metal device are not described; only the code `UNAVAILABLE` is named. | `verified` is a boolean and the node treats `false` as a failed self-test; `gpuRecommendedMaxWorkingSetBytes` may be `null`; error responses carry `code` (closed set: `BAD_REQUEST`, `UNKNOWN_OP`, `UNSUPPORTED_VERSION`, `UNAVAILABLE`, `FAILED`) and a fixed `message` that never echoes request content, a blob, a path or a token. |
| MAC-PROTO-6 | R3-CLOSURE-12, R3-OVERCLAIM-7 (independence of a second implementation) | The Swift codec and the Kotlin codec were written by the same author from the same schema; agreement is not independent confirmation. | The vectors are tagged SELF-ORACLED and the agreement is called "cross-lane". `helper-protocol/tools/gen_vectors.py` writes the expectations as literals and contains no codec. Two size-boundary tokens (`{PAD}`, `{ZEROS}`) keep the files small. |
| MAC-JSON-1 | `desktop/node-core/.../json/StrictJson.kt` (not this track's file) | `StrictJson.hex4` reads `\u` escapes with `Character.digit(c, 16)`, which accepts non-ASCII decimal digits: `\u` followed by the four Arabic-Indic digits for 0041 parses as `A`. RUN (LAB): `node-core StrictJson on that input: {"x":"A"}`; this track's parser on the same input: `REJECTED: bad unicode escape at offset 8`. Swift has a second trap: `String` equality is canonical equivalence (U+00E9 equals `e` + U+0301, and U+212A equals `K`), so a `Set<String>` of member names would call two different names duplicates. | This track has its OWN strict parser (`helper/HelperJson.kt`) instead of depending on a quirk, and the Swift lane compares UTF-8 bytes everywhere. Vectors cover both (HP-REQX-041 and HP-REQX-068). FINDING for the desktop-core owner: `StrictJson` accepts non-ASCII digits in `\u` escapes; it was NOT edited (not this track's file). |
| MAC-KEY-1 | macos.md 5 ("T2 → self-test → T0 on first creation only; never silently downgrade an existing T2 identity") | Silent on a helper that is merely unreachable, on both key files present, and on the order of the binding and the key. | (1) A helper that cannot be reached is NOT read as "no Enclave": the exception propagates and no key of either tier is made, so a temporarily missing helper can never pick the weaker tier. (2) An existing T2 identity whose blob is missing, corrupt, not private, or fails its self-test is `NIK_UNAVAILABLE` and never falls back to T0 and is never replaced. (3) Both `nik.se` and `nik.p8` present is refused. (4) The platform binding is written BEFORE the key, and an identity with no binding is treated as migrated. (5) The login keychain is REJECTED and there is no T1: `NikTier` has two members and the reasons are printed by `asom doctor`. (6) `SecureEnclaveNik.delete()` forgets the node's copy of the blob only: the helper has no operation that deletes an Enclave key, and a copy made earlier by any process still works until the Mac is erased. The docs and the doctor say so. |
| MAC-KEY-2 | macos.md 5 (T0 "optionally passphrase-wrapped") | A passphrase wrap needs a passphrase source and a KDF the spec does not name. | NOT BUILT. The T0 file is always unwrapped (which is what "serve while logged out" would opt into anyway). |
| MAC-KEY-3 | macos.md 3.5 (`se.create` returns `spki`, 91 bytes) | Nothing says the node checks it. | Every SPKI is parsed as a real P-256 key (the JCA checks the point is on the curve) before it is stored or trusted; the T2 self-test signs a fresh 32-byte challenge and verifies it with the JCA in the r\|\|s form at creation and at every open. Whether a REAL Enclave accepts a key made by a Developer-ID-signed helper without entitlements is AM01 (S-M1, owner device): the code was tested against a JCA-backed fake enclave only. |
| MAC-LOCK-1 | macos.md 3.2 (the node lock file is "created 0644 by whoever runs first") | A file created 0644 by user A cannot be opened for writing by user B, so B could never take the exclusive lock even after A's node is gone. | The file is created 0666 and opened with `NOFOLLOW_LINKS` and `CREATE_NEW`, so a symbolic link planted in the world-writable `/var/tmp` is never followed and its target never chmod-ed (a test plants one). A lock file that exists but cannot be opened for writing is `Unavailable` (reason shown), not silently ignored. A local user can always stop lending by holding the lock; it is a guard against the owner's own two agents, not a security boundary. NOT TESTED: two different real users (the container runs as root, for whom every file is writable). |
| MAC-LOCK-2 | macos.md 3.2 | Silent on deleting the lock file. | Never deleted (in a sticky directory only its owner could) and nothing is written to it. |
| MAC-LOCK-3 | (found by a test) | POSIX record locks belong to the PROCESS: closing ANY descriptor of the file drops ALL of the process's locks on it. A second `NodeLock` in the same JVM (the doctor checking the lending slot while the node holds it) that opened the file and closed it after a failed attempt silently RELEASED the first holder's lock; a separate JVM then acquired it. | A per-process registry: a second attempt in this JVM is answered `HeldByOther` before any descriptor is opened. `PathsAndGuardTest` runs a real second JVM against a held lock; mutation M20 (registry removed) is killed by it. |
| MAC-POWER-1 | macos.md 2.1 (power source `ac \| battery`), `DesktopRules` | A desktop Mac on a UPS reports `battery` with no battery level; `DesktopRules` blocks only when `hasBattery && source != AC`, so it would serve on a UPS. | A Mac "has a battery" when it reports a level OR runs on battery power at all, so a UPS-backed desktop does not lend. The percentage is the level rounded DOWN. Low Power Mode is `saver` and is a condition block (`low-power-mode`). Several holds share ONE assertion (taken by the first, released by the last); both `LockKind`s map to it; a refused hold is a state, not an error loop. |
| MAC-SLEEP-1 | macos.md 2.1 (a sleep drain: acknowledge within 2 s) vs `NodeRuntime`/`FsmConfig` | `HostRules` has no member for the sleep budget, so `NodeRuntime` builds its FSM with the node-core default `sleepBudgetMs = 5000`. | The 2 s budget is implemented where this track owns it: `MacPowerPort` acknowledges when the drain returns or after `ackBudgetMs` (2,000), once per token, whatever the FSM's own deadline; `MacRules.SLEEP_BUDGET_MS = 2000` is the value a real FSM must be built with, and a test builds a `ProviderFsm` with it and shows the drain deadline is `now + 2000`. FINDING for the desktop-core owner: `NodeRuntime` cannot yet take a host's sleep budget. |
| MAC-SLEEP-2 | macos.md 10.1 (`SleepDrainTest`: "sleep.will → listener closed, INFER_END interrupted, outcome rows, ack ≤ 2 s") | There is no listener, no inference stream and no outcome-row writer yet (later tracks). | The test asserts what exists: the listener callback receives `SLEEP_IMMINENT`, the real `ProviderFsm` closes the listener (`CLOSE_LISTENER`) in the same step, and the ack is sent once within the budget; INFER_END and the outcome rows are NOT tested here. |
| MAC-PRES-1 | R3-OVERCLAIM-4(c) (presence differs per OS) | macOS lends only after 10 minutes of HID idle or when the screen is locked, and only when the console user is the node's user; Linux lends while someone is at the keyboard. | Implemented as macos.md 2.1 says, with every unknown input counted as PRESENT (`console-user-unknown`, `presence-unreadable`, `input-idle-unreadable`), another console user as presence even when idle and locked, and the user-visible copy to be per OS (the doctor states the rule). The idle counter is HID keyboard, mouse and trackpad only; whether it and the lock state track real use is S-M8 (NDV). The table test runs all 3 x 7 x 3 = 63 combinations against an independent oracle. |
| MAC-PRES-2 | macos.md 2.1 (idle 10 min) with design 7.4 LP-2 (10-minute hold-down) | Whether the two compose. | They COMPOSE (the more conservative reading, as on Windows, WIN-PRES-1): presence signals are emitted while the user is present and the hold-down runs from the last one. RUN (LAB, fake clock through the real `NodeRuntime` and FSM): the Mac starts SERVING 1,198 s after the last input; still ARMED 19 minutes after it. The idle threshold cannot be configured below 600,000 ms. |
| MAC-THERM-1 | macos.md 2.1 (thermal band mapping PROVISIONAL) | The four-level `thermalState` has no temperature and no hysteresis rule. | `nominal` is band 0, `fair` 1, `serious` and `critical` 2 (HOLD); no hysteresis is added (the OS state is already smoothed); the reading carries no temperature it did not measure; an unreadable or unknown state is band 2 (unknown heat is the unsafe answer). |
| MAC-GPU-1 | macos.md 2.1 and AM12, RM15 | No per-process GPU accounting exists without root. | `other_busy = deviceUtilPermille - own` (never negative), an ESTIMATE that can over-report (drain earlier, the conservative direction) and be late to yield to a GPU-heavy app; `own` is 0 because `NoopEngine` runs no Metal work; a tick whose counter cannot be read is `null`, never zero; no counter means the rule is OFF and the doctor says so; a lost helper does not decide that the counter is absent. |
| MAC-NET-1 | macos.md 4.1 | Which interfaces and addresses; how the overlay and the LAN differ; what a change is. | `utunN` carrying `100.64.0.0/10` or `fd7a:115c:a1e0::/48` is the overlay (the lowest name among IPv4 candidates, deterministic); `enN` on a user-confirmed network at a private or link-local address is the LAN; IPv6 link-local needs a scope; the Tailscale ULA block is excluded from the LAN set (it lies inside `fc00::/7`, as WIN-NET-2); a wildcard, loopback, multicast or public address is never bindable whatever a caller composes (`isBindable`); no kernel TUN with an overlay address is "overlay mode unsupported: use a kernel TUN" and never loopback. After a wake a binding is `Same`, `Moved` (utun renumbered) or `Lost`; extra addresses do not flap. This module decides only; it binds nothing. |
| MAC-NET-2 | macos.md 4.2, AM09 (a LAN connect blocked by Local Network privacy surfaces as `EHOSTUNREACH`) | The inference is unverified, and a really unreachable host gives the same error. | `local-network-denied` is produced only for "No route to host" to a LAN-class destination, is flagged `inferred = true`, and its explanation says both possibilities. An overlay or public destination is never classified as denied (VPN traffic is not local network). Real behaviour is S-M7 (NDV). |
| MAC-CTL-1 | macos.md 3.3 c and FM27 (`getpeereid` uid check; `callerPkg = local-uid:<uid>`) | The JDK exposes `SO_PEERCRED` as a user NAME and a group name, not a number (the same as Linux, linux ERRATA ERR-DL2-1). | Peers are compared by user name against `user.name`; a uid the JDK cannot resolve arrives as digits, never equals a name and is denied; an unreadable peer is denied; there is no weaker fallback. `callerPkg` is `local-uid:<user name>`, the form the Linux host uses. The check runs in both directions (`authorizeClient` for the node, `verifyServer` for the CLI), and the socket directory must be a real directory owned by this user with mode 0700. |
| MAC-CTL-2 | R3-CONFORMANCE-13; `desktop/tools/check_law.py`; `desktop/ERRATA.md` ERR-SCOPE-1, ERR-DL2-3; windows WIN-CTL-1 | The assignment lists an AF_UNIX control socket, but check_law (not editable by this track) forbids a listener API in any main source except the single `ControlServer.kt`, and nothing may listen by default. | `MacControlSocket.start` throws `NotYetImplementedException("control-socket bind (AF_UNIX)", "MC4 / D-v2 (D25, D23)")` and declares it through `PartiallyImplemented`, so the selftest reports it by name and proves the declaration true. | MAC-DOCTOR-1 | macos.md 3.3, 4.1, 4.3, 8.3 (doctor reads `socketfilterfw`, `pmset`, Tailscale) | Which tools, with which arguments, and what their output looks like. | `SystemProcessRunner` runs only `pmset -g assertions`, `pmset -g batt`, `socketfilterfw --getglobalstate`, `socketfilterfw --getappblocked <abs path>`, `ioreg -r -k AppleClamshellState -d 4` and `pgrep -fl tailscaled`, each by absolute path with exactly those arguments, with an empty environment, closed stdin and capped output (`ps -axo command` was refused because it would read every process's command line, which can carry secrets). The doctor never changes anything. |
| MAC-HELPER-1 | macos.md 3.5, 7.3 (AM26: a stock launcher passes the caller's environment) | Where the helper executable comes from is unspecified; the JVM passes its environment to a child. | The helper path comes ONLY from the system property `asom.mac.helper` (absolute; no PATH lookup, never an environment variable, so a same-user process cannot choose the program the entitled node spawns); the child gets an EMPTY environment except `TMPDIR`; stderr is discarded; the helper is started only by the first call, restarted at most once per minute (a failed start counts), and its stdin EOF is its shutdown. |
| MAC-HELPER-2 | macos.md 10.1 (`Package.swift`: "HelperProtocol (pure Swift, builds on Linux), asom-mac-helper (executable)") | The executable target cannot compile on Linux if it imports Apple frameworks. | Every macOS-only Swift file is wrapped in `#if os(macOS)` (a test checks each opens and closes with the guard) and `main.swift` on any other system says "macOS only" and exits 69, so `swift build` and `swift test` work on Linux. The executable target uses Swift language mode 5 to limit strict-concurrency friction in code nobody could compile. |
