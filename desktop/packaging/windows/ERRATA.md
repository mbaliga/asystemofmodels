# windows ERRATA: spec defects and gaps met by the `windows-w0-w2` track, and the reading taken

Where a spec defect (`docs/design/mesh/REVIEW_ROUND3.md`, or a defect found while building) touches what this track implements,
the CONSERVATIVE reading was taken and is recorded here. Nothing was silently guessed. Ids are `WIN-*` so they never collide with
`desktop/ERRATA.md` (the desktop-core track's) or `lab/ERRATA.md`. Evidence labels: `LAB` (Linux container), `CI-APPROX`,
`CI-ONLY / NOT RUN` (needs a hosted Windows runner), `NDV` (needs a real device).

[ ]` are refused because `-InterfaceAlias` would widen the rule. The elevated apply step, `asom mesh firewall enable`, is NOT built. |
| WIN-FW-2 | windows.md 4.2 ("the probe finds a matching allow rule and no block rule scoped to asom's program path"; "read rules (netsh parse; COM INetFwPolicy2 later)") | `netsh advfirewall firewall show rule` prints localised labels and does NOT print the interface alias, and its "Rule Name" is the display name, not the `-Name`. | The gate parses the ENGLISH output only and **fails closed** on anything else (zero judgeable rules is `FIREWALL_PROBE_FAILED`, never "no rules so open"; a probe that throws or times out is the same). Our allow rule is recognised by its DISPLAY name prefix `asom peer listener`, so a foreign broad rule never stands in for the owner's consent to asom's own rule. It also requires enabled, inbound, Allow, TCP, the exact peer port, asom's program or service, a remote scope other than Any, and a profile containing Private. Block rules that name asom (program, service, display prefix), that cannot be judged but name asom, or that block the port for everyone count and win. **The gate cannot prove the rule is scoped to the interface alias** (netsh does not print it), that the current network profile is Private, or that a Group Policy has not disabled local rule merge; `asom doctor` says so. The parser is exercised against real output only by `FirewallProbeIT`. |
| WIN-SLEEP-1 | R3-OVERCLAIM-8 (windows.md 2 says a held power request keeps a Modern Standby machine in NoCS through idle display-off AND that display-off on Modern Standby is a hard `os_sleep_imminent` drain) | Two rules that cannot both hold. | ONE rule chosen: display-off (and `PBT_APMSUSPEND`) is `SLEEP_IMMINENT`, display-on and resume are `RESUMED`, dimming is neither. This applies to EVERY Windows machine, including a desktop on S3 where nothing suspends. Serving through display-off (service mode on AC only) is NOT implemented and needs an owner ruling. Consequence, stated: with a display timeout shorter than the presence idle threshold the lending window can be empty. `asom doctor` says lending ends when the display turns off. The W8 device item that measures the real lending window is in `docs/DEVICE_CHECKLIST_WINDOWS.md`. |
| WIN-PRES-1 | windows.md 2.1 (idle at least 10 min) with design 7.4 LP-2 (10-minute hold-down after the last presence signal) | Whether the two compose. | They COMPOSE, the later of two readings: presence signals are emitted while the user is present, and the hold-down runs from the last of them, so lending starts about 20 minutes after the last input. The test computes the bounds from the spec's numbers (10 min idle, 600,000 ms) by simulation through the real `NodeRuntime`. The idle threshold cannot be configured below 600,000 ms (as the hold-down cannot). |
| WIN-PRES-2 | windows.md 2.1 (presence: "GetLastInputInfo idle at least 10 min, session locked, or no full-screen/D3D app"); R3-OVERCLAIM-4(c); AW07 | The clause list reads as alternatives; the WTS lock flag has a disputed polarity between Windows versions; service mode (session 0) cannot see the user's shell; gamepad input does not reset the idle counter. | Lending is allowed only when (idle for 10 minutes OR locked) AND no full-screen, D3D, presentation or full-screen Store app runs (R3-OVERCLAIM-4(c): Windows lends only after ten minutes idle or when locked). Every unreadable input counts as present. "Locked" needs TWO independent signals to agree (the WTS lock flag AND `SHQueryUserNotificationState` = NOT_PRESENT), so a wrong polarity cannot make an active session look locked. Service mode has only the console session's idle time and NO full-screen check, and with no console user it does not lend unless `serveWhileLoggedOut` is on (default off). `asom doctor` says both, and that gamepad input does not count. Not verified: any of this with a person at a keyboard (S-W6, NDV). |
| WIN-POWER-1 | windows.md 2.1 (`GetSystemPowerStatus` rules [FW12]) | Silent on contradictions and on unknown flags. | AC is `ACLineStatus = 1`, or no battery (`BatteryFlag = 128`) with 1 or 255. Offline mains with no battery is a contradiction and is UNKNOWN, which blocks. `BatteryFlag = 255` (unknown) counts as "has a battery", so an unreadable battery can never look like a desktop; an unreadable status is UNKNOWN with a battery. A refused power request is a state, not an error loop: `hold` returns a hold that holds nothing, `lastHoldError` says why and `asom doctor` shows it. |
| WIN-GPU-1 | windows.md 2.1 and AW05 (`other_busy = total - own`) | Which engine, which adapter, and how to cap. | Per engine (keyed by luid, phys, engine and type) total is the sum over processes capped at 100 %, own is this process's share, other is the difference; the device, own and other figures are the BUSIEST engine of any adapter. That can over-report others (a video-decode engine busy with someone else) and so drain earlier than needed: the conservative direction. A rate counter's first collection, an empty instance list and a list with nothing parseable are `null`, never zero. Whether the wildcard counter picks up processes that start later is unverified (AW05, S-W4). |
| WIN-THERM-1 | windows.md 6 and AW06 | No thermal source on most consumer PCs, no trip points on Windows. | With no counter: band 0, no sensors, `hasSignal` false; the doctor says benchmark plans `standard` and `sustained` must refuse (`NO_THERMAL_SIGNAL`) and only `quick` may run (the bench itself is not this track's). With zones: hold at or above the PROVISIONAL 85 C (`thermalNoTripHoldMilliC`, invented by the desktop track because the alternative, never seeing heat, is unsafe), queue within 10 C below, raising immediate, lowering 3 C and 10 s (ERR-THERM-1). Implausible values are ignored; a stuck value stops counting as a signal but a stuck HOT value still holds. The throughput-decline detector the spec names as the fallback (B7) is NOT built. |
| WIN-NET-1 | windows.md 4.1 ("every (re)bind re-checks eligibility; a change means DRAINING") | Which changes count. | A changed interface index, the loss of the bound address, a down or missing interface, a withdrawn LAN confirmation, and any address-level problem count. Extra addresses appearing on the interface (DHCP, IPv6 temporary addresses) do NOT, or the node would flap. A link-local IPv6 address without a scope is refused (it names no interface). |
| WIN-NET-2 | windows.md 4.1 (LAN: RFC 1918, link-local or ULA) | Tailscale's ULA block `fd7a:115c:a1e0::/48` lies inside `fc00::/7`, so an overlay address would pass as a "LAN" address. | Overlay ranges (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`) are excluded from LAN eligibility first. | WIN-KEY-1 | windows.md 5, AW01, AW02, AW03, S-W1, S-W2 | The PCP P-256 claim, the r||s form and the machine-key DACL are unverified. | Built from the documented signatures and covered by fakes backed by the JCA (real ES256 maths, real verification): every signature is checked to be 64 bytes and to verify against the exported public key, at creation (the self-test) and in the tests. | WIN-MUTEX-1 | windows.md 3.2 (`Global\asom-node`; "whichever of the two starts second refuses to start") | The obvious implementation (`CreateMutexW`, then look for `ERROR_ALREADY_EXISTS`) leaks: JNA turns that error into an exception that REPLACES the returned handle, so the handle to the existing mutex is never closed and keeps the object alive for the life of the process (found by reasoning while writing `MutexIT`, whose "taken again after release" step would have failed on the first hosted run). | `Kernel32Mutex` probes with `OpenMutexW` first (an existing mutex is opened, the handle closed at once, and the answer is "held by another"; `ERROR_FILE_NOT_FOUND` means create; access denied means it exists under another account), and creates only when it does not exist.
