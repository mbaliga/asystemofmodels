# ubuntu-touch ERRATA: spec defects and gaps met by the `ubuntu-touch-ut0` track, and the reading taken

Where a spec defect (`docs/design/mesh/REVIEW_ROUND3.md`, or one found while building) touches what this track implements, the
CONSERVATIVE reading was taken and is recorded here. Nothing was silently guessed. Ids are `ERR-UT-<area>-<n>`.

| ERR-UT-CTL-1 | ubuntu-touch.md 7.3 | The spec fixes the frame set and the 1 MiB cap but not what happens on a malformed line, an oversize line, an unknown type or a second `hello`. | Fail closed and say nothing about it: the node ends the session with one FIXED line on stderr (`asom-ut: protocol violation <REASON>`, `REASON` from a closed enum of 14) and exit 65, writes no frame, echoes no part of the line. | ERR-UT-CTL-2 | ubuntu-touch.md 7.3 and 10.4 | (a) `pair`, `revoke` and `export` have no UT-0 implementation and the closed `error` code set has no "not implemented". | ERR-UT-CTL-3 | ubuntu-touch.md 7.3 (frame names only) | Member names are not given. | Every frame is one object whose first member is `t` (the type). `peers{open|close}` is `{"t":"peers","op":"open"}`; the node's `peers` and `rows` frames carry `list` and `rows`; `sas{code}`, `state{node,sessions,lending}`. `node` is one of `idle|active|interrupted`, `lending` is `off` until UT-2. Decoding is strict (the lab's tokenizer: integers only, no duplicate names, no lone surrogate), closed (an unknown member is refused) and bounded (request ids, model names, message counts and lengths). |
| ERR-UT-ERR-1 | ubuntu-touch.md 7.3 error mapping, design 7.6, RL1 | The three rules can all apply at once (no paired peer: "a model held by no paired peer" and "no paired peer and no keys"). | The v1 router's order, so that RL1's oracle holds: `local-only` is `LOCAL_ENGINE_ABSENT` (also with peers); an unknown concrete model (when a catalogue is supplied) is `MODEL_UNKNOWN`; no paired peer is `NO_PROVIDER_KEY`; a concrete model held by no peer is `MODEL_UNKNOWN`; a policy name with peers that hold no model is `NO_PROVIDER_KEY`; every holder cooling is `ALL_PROVIDERS_COOLING`. With no peer the result equals the REAL `Router.plan` on a key-less universe (7 vectors compare them). UT-0 has no catalogue (`null`: the unknown-model rule is skipped, not guessed). |
| ERR-UT-FSM-1 | ubuntu-touch.md 3.3 | FREEZING and RESUMING are described as phases with work in them; `interrupted` is the only non-idle/active wire value. | Two-phase: entering FREEZING or RESUMING returns the work as effects (`CancelAttempts`, `CloseSessions(<why>)`, `WriteInterruptedRows`, `ReleaseDisplay`, `ForceLedger`); the session performs it and feeds `Drained` or `Resumed`. Each stop is announced, so a UI that is still running sees `interrupted` before `idle`. Wire mapping: STARTING and IDLE are `idle`; FREEZING, FROZEN, RESUMING and LEDGER_FAIL are `interrupted` (LEDGER_FAIL is also answered on every request with `LEDGER_UNAVAILABLE`). Nothing is ever retried. |
| ERR-UT-FSM-2 | ubuntu-touch.md 3.3, 3.4 (L-UT1: "within the last 10 s", "after 10 s"; "gap > 3 s"; "for 5 min") | Boundaries are not fixed. | The UI counts as active while its last `active` report is AT MOST 10,000 ms old; the watchdog fires on a gap STRICTLY over 3,000 ms; the idle close fires at 300,000 ms of no work. Each boundary has a vector on both sides (UTC02) and is mutation-checked. After a stale-`active` freeze the node stays FROZEN until a fresh `active` arrives (a drain resumes only if the last report is recent). |
| ERR-UT-FSM-3 | ubuntu-touch.md 3.4 (L-UT2), 7.3 (closed frame set) | L-UT2 holds the display "between INFER_BODY and its outcome row", but no frame tells the UI when that is. | The FSM emits `HoldDisplay` and `ReleaseDisplay` (the node-side truth, vector-checked), but nothing carries them over the closed channel. Closing the gap needs one new frame, which is a change to the channel and needs owner sign-off before UT-1. |
| ERR-UT-FSM-4 | ubuntu-touch.md 3.3 (`closedBy = suspend`) | Only `suspend` is named. | Effect labels use `freezing`, `idle`, `shutdown` and `suspend`; they are not ledger vocabulary until D23 fixes it. UT-0 writes no ledger row from these. |

## ERR-UT-CLICK-2 (orchestrator, first hosted Clickable run 2026-09-30)

ERR-UT-CLICK-1 assumed Clickable substitutes `@APPARMOR_POLICY@` in the install directory. It does not: `clickable build` failed with "Failed reading .../install/asom.apparmor, it is not valid json", because Clickable parses the AppArmor file as JSON first. `asom.apparmor.in` keeps the placeholder and CMake `configure_file(@ONLY)` fills the policy version `2404.1` into the installed file (the value the framework `ubuntu-touch-24.04-1.x` maps to; Clickable rewrites it itself). `@CLICK_ARCH@` and `@CLICK_FRAMEWORK@` in the manifest and desktop file are unchanged. The static checks still accept the old placeholder form.
